```bash
npm install bso5                 # core only
npm install bso5 bso5-components # core + components
```

## 1. State

### `Signal<T>`

An atomic reactive value.

```ts
class Signal<T> {
  constructor(initial: T);
  get value(): T;                 // read; inside effect() registers a dependency
  set value(next: T);             // write; notifies only on real change (Object.is)
  peek(): T;                      // read without tracking
  update(fn: (current: T) => T): void;   // write derived from the current value, untracked read
  subscribe(cb: () => void): () => void; // manual subscription; returns an unsubscribe
}
```

- `set` compares with `Object.is`: `signal(0); s.value = 0` notifies nobody.
- `subscribe` callbacks run **synchronously** after the write (inside `batch` — once at the end).
- Subscriptions live in a `Set`, so re-subscribing the same callback does not duplicate it.

### `signal<T>(initial: T): Signal<T>`

```ts
const count = signal(0);
```

### `Reactive<T extends object>`

Deep reactive proxy over a plain object or a class instance.

```ts
class Reactive<T extends object> {
  constructor(raw: T);            // throws if the object is already wrapped
  get value(): T;                 // proxy tree; nested objects are wrapped lazily
  get target(): T;                // raw object: reads/writes are not tracked
  watch(path: ((t: T) => any) | string, cb: () => void): () => void;
  dispose(): void;                // stops subscriptions and effect tracking
}
```

- `watch(x => x.user.name, cb)` fires on `x.user.name = …` **and** on `x.user = { … }`
  (the nested path re-binds to the new object).
- Index notation works: `x => x.rows[0].done`, `'rows.0.done'`.
- The accessor must be a **plain, pure property chain**: it is executed once to trace
  the path. Expressions (`x => x.a + 1`), method calls and `async` are rejected —
  `watch()` throws, `$()` returns a non-reactive value.
- `dispose()` makes the proxy inert for reactivity: reads and writes keep working,
  subscribers simply stop being notified.

**What is not wrapped** (passes through, no proxy, no reactivity):
`Map`, `Set`, `WeakMap`, `WeakSet`, `Promise`, `Date`, `RegExp`, `Error`,
`ArrayBuffer` and typed arrays, `Blob`/`File`, `AbortController`/`AbortSignal`,
`FormData`, `URL`/`URLSearchParams`, and any DOM node.

```
model.value.cache.set(k, v);    // works, but does NOT notify subscribers
model.value.cache = new Map(…); // notifies — replace the value as a whole
```

Reason: a built-in method invoked through a proxy receives the proxy as `receiver`
and throws `TypeError: Method Map.prototype.set called on incompatible receiver`.

### `watch(source, path, cb): () => void`

Free-standing subscription: `source` is either a `Signal` (then `path` is ignored) or a
`Reactive` value/proxy (then `path` is an accessor or a dotted string).

```ts
const stop = watch(model.value, x => x.user.name, () => { /* … */ });
```

### `getPropertyName(fn): string | null`

Traces an accessor path (`x => x.items[0].title` → `'items.0.title'`). Returns `null`
when the accessor is not a plain property chain. Exported for tooling; not needed in
regular code.

### `Reactive` vs `Signal`: which one

| Need | Use |
| --- | --- |
| a single value with simple updates | `Signal` |
| an object/model with nested fields and path-level subscriptions | `Reactive` |
| a value derived from several sources | `computed` |
| a value usable both as an attribute and as text | `$()` |

## 2. Reactive computations

### `effect(fn, options?): () => void`

Runs `fn` immediately and re-runs it whenever any `Signal` or `Reactive` property it
read changes (synchronously, unless inside `batch`).

```ts
interface EffectOptions {
  onError?: (error: unknown) => void;
}
```

- Returns a stop function (idempotent).
- Dependencies are reset before every run: what is no longer read stops triggering.
- An exception inside the effect is **not** propagated to the code that wrote the
  signal. The default sink is `console.error`, overridable per effect (`onError`) or
  globally (`setEffectErrorHandler`).
- An effect that both reads and writes the same signal does not recurse: synchronous
  recursion is guarded (`rec.running`). Still, prefer `peek()`/`update()`.
- Nested effects are supported; an effect created inside an ownership scope stops
  with that scope (see §5).

### `setEffectErrorHandler(handler: ((error: unknown) => void) | null): void`

Global sink for effect errors. `null` restores `console.error`.
Priority: per-effect `onError` → global handler → `console.error`.
If the handler itself throws, the error goes to `console.error` and the graph keeps going.

### `computed<T>(fn): Signal<T>`

A derived value: recomputes when a dependency changes and notifies readers only when
the result actually changed (`Object.is`).

```ts
const count = signal(2);
const doubled = computed(() => count.value * 2);   // Signal<number>
doubled.value;                                      // 4
```

- Recomputation is **eager** (on dependency change, not on read): there is no lazy cache.
- Returns a `Signal`, so it fits `$()`, `each`, `<Show when>` and plain reads inside `effect()`.
- Inside a scope (`mount()`, `<For>`, `<Show>`) it stops together with the scope.

### `batch<T>(fn: () => T): T`

Groups writes: dependent effects and listeners run once at the end of the block.
Nested `batch` calls collapse into one. Listeners are deduplicated by identity,
effects by record.

```ts
batch(() => { a.value = 10; b.value = 20; });  // one effect run
```

### `untrack<T>(fn: () => T): T`

Runs `fn` without registering what it reads as a dependency of the current effect.

```ts
effect(() => { render(tracked.value, untrack(() => ignored.value)); });
```

## 3. Binding to the DOM: `$()`

### `$(source, path?): BoundValue<T>`

The bridge between state and markup. Accepts a `Signal` (`$(countSignal)`) or a
`Reactive` value/proxy plus an accessor (`$(model.value, x => x.user.name)`).
The result is used as a child or as an attribute value; the DOM is patched in place.

```tsx
<p>Count: {$(count)}</p>
<input value={$(model.value, x => x.name)} />
<div style={{ color: $(model.value, x => x.color) }} />
```

- `BoundValue<T>` is an object with the `REACTIVE_VALUE` marker, a `value` getter and
  `subscribe`. Type guard: `isBoundValue(v)`.
- `$()` over a **plain** object (not `Reactive`) resolves once and never updates.
- A root and a nested proxy behave differently when an intermediate link is replaced:
  - `$(model.value, x => x.rows[0].title)` — the path is resolved from the root, so the
    subscription survives `model.rows[0] = {…}`;
  - `$(row, x => x.title)`, where `row` is a nested proxy, binds **to that object**:
    writes to its fields are seen, while replacing its slot in the parent is not (the
    value stays from the old object). Bind from the root when that matters.
- Do not interpolate it into a string: `` `total: ${$(count)}` `` yields `[object Object]`.
  Bind the child/attribute itself, not a string around it.
- The accessor is a plain property chain (see `Reactive.watch`).
- Inside an ownership scope the binding is released together with its node (`releaseBindings`).

## 4. Elements: `h()` and JSX

### `h(tag, attrs?, ...children): HTMLElementTagNameMap[tag]`

Universal factory, typed per HTML tag. The JSX transform calls the same implementation
(`hEl`), so the rules below are identical for both.

`attrs` may be an object or a function `(el) => void`:

```ts
h('input', el => el.focus());
```

**Attribute rules:**

| Key | Value | Behaviour |
| --- | --- | --- |
| `class`, `className` | string | `el.className = value` (synonyms; if both, the last one wins) |
| `style` | string | `setAttribute('style', value)` |
| `style` | object | per property: `el.style[prop] = value` |
| `style` value | number | **always** gains `px`: `{ width: 10 }` → `10px`; unitless props (`opacity`, `zIndex`) must be strings |
| `style` value | `$()` | the property becomes reactive |
| `onClick`, `onInput`, … | function | `addEventListener('click' / 'input' / …)`; camelCase required |
| `onDoubleClick` | function | the `dblclick` event |
| `onInputCapture` | function | capture phase (`{ capture: true }`) |
| `value`, `checked`, `selected`, `disabled` | any | assigned as a **property**, not a string |
| `value` on `<select>` | any | applied **after** its `<option>`s exist |
| `dataset` | object | `el.dataset[k] = String(v)` |
| `ref` | `(el) => void` | called with the created element (before children are appended) |
| `data-*`, `aria-*`, anything else | any | `setAttribute` when the element has no such property |
| any key | `null`/`undefined`/`false` | `removeAttribute(key)` |
| any key | `$()` | applied now and kept in sync with the source |

**Children rules:** `string`/`number` → text node; `null`/`undefined`/`true`/`false` →
nothing; array → recursive; `Node` → as is; `$()` → a live text node.

**Not supported:** object `ref` (`{ current }`), option-free `on*Capture` semantics,
`class` normalization from arrays/objects, `dangerouslySetInnerHTML`.

### `hEl(tag, attrs, children[]): HTMLElement`

Same, but `children` is an array (used by the JSX runtime; rarely useful publicly).

### Low-level exports

Used inside `h()` and `<For>`; public because custom renderers and wrappers need them.

| Export | Signature | What it does |
| --- | --- | --- |
| `flattenChildren` | `(children: Content[]) => Array<Node \| string \| number \| BoundValue>` | Flattens nested arrays, drops `null`/`undefined`/`true`/`false` |
| `appendChildren` | `(parent: Node, children: Content[]) => void` | Appends children by the §4 rules: strings → text nodes, `$()` → live text nodes, `Node` as is |
| `boundTextNode` | `(value: BoundValue) => Text` | Creates a text node with a binding; the binding is registered and released by `releaseBindings` |
| `applyAttr` | `(el: HTMLElement, key: string, value: unknown) => void` | Applies a single attribute by the §4 table, including `$()` values and `ref` |

### `parseEventProp(key): { event: string; capture: boolean }`

`'onDoubleClick'` → `{ event: 'dblclick', capture: false }`,
`'onInputCapture'` → `{ event: 'input', capture: true }`.

### JSX runtime

```ts
createElement(tag, props, ...children): Node
jsx / jsxs / jsxDEV(tag, props, key?): Node   // react-jsx entry points
Fragment({ children }): DocumentFragment
```

- A function tag is called with the props (including `children`) and must return a `Node`.
- `key` never lands in the props of intrinsic tags; for function components it is folded
  back into the props (needed by `<For key>`).
- Types: `JsxChild`, `JsxNode`, `Component<P>`, `DOMAttributes`, `namespace JSX`.

## 5. Lifecycle and effect ownership

### `mount(target, view): { node, dispose }`

```ts
function mount(target: Element | DocumentFragment, view: Node | (() => Node)): Mounted;
interface Mounted { readonly node: Node; readonly dispose: () => void; }
```

- Pass a **thunk** (`() => <App />`) to hand ownership of the view's effects to the
  mount scope, so they stop with it. A ready-made node is accepted too, but its effects
  were already created outside any scope.
- `dispose()`: `releaseBindings` over the subtree → `dispose(scope)` → node removal.
  Idempotent.

### Ownership scopes

```ts
interface Scope { readonly stops: Set<() => void>; disposed: boolean }
createScope(): Scope
dispose(scope): void                       // idempotent, rejects new registrations
runInScope<T>(scope, fn: () => T): T       // effects created inside fn belong to scope
onScopeDispose(fn): void                   // cleanup on dispose; no-op outside a scope
getCurrentScope(): Scope | null
```

`effect()` called inside `runInScope` registers its stop function in that scope.
`<For>`, `<Show>` and `mount()` build scopes themselves.

**Contract boundary:** ownership exists only where there is `mount()`, `<For>` or
`<Show>`. A module-level `effect()` has no owner — stop it manually.

### `releaseBindings(root: Node): void`

Stops every `$()` binding (text, attributes, style) inside the subtree. Idempotent;
effects are not touched — that is what scopes are for.

## 6. Lists and conditionals

### `<For each={…} key={…?}>{(item, index) => …}</For>`

```ts
interface ForProps<T> {
  each: ReactiveSource<readonly T[]>;
  key?: (item: T, index: number) => unknown;
  children: (item: T, index: number) => JsxChild;
}
type ReactiveSource<T> = T | (() => T) | Signal<T> | BoundValue<T>;
```

Renders between comment anchors, without a wrapper element.

**Without `key`** — the whole list re-renders on any change; item functions must be
cheap; effects and bindings of the previous pass are released.

**With `key`** — keyed reconciliation:

- DOM nodes are reused and moved (`insertBefore`), and only nodes that are out of place
  are moved;
- while a key stays in the list its nodes are **not re-rendered** (key = identity):
  changed data does not appear by itself — bind fields with `$()` or change the key
  (fingerprint recipe in [GUIDE.en.md](./GUIDE.en.md#4-lists-with-the-keyed-mode));
- the rendered index is captured at first render;
- duplicate keys collapse into one group (the first occurrence wins);
- when a key leaves the list, its group's effects are stopped and bindings released.

### `<Show when={…} fallback={…?}>{…}</Show>`

```ts
interface ShowProps {
  when: ReactiveSource<boolean>;
  fallback?: JsxChild | (() => JsxChild);
  children: JsxChild | (() => JsxChild);
}
```

- Also wrapper-free (comment anchors).
- `children`/`fallback` are a **thunk** or a ready `JsxChild`.
- A thunk is rebuilt on every show and torn down on every hide: a hidden branch stops
  reacting to model changes.
- A ready node cannot be re-bound (its subscriptions live in a `WeakMap` keyed by the
  node itself), so it is cached and lives until the whole `<Show>` is disposed. Need a
  real teardown — pass a thunk.
- A node branch is not rebuilt when the decision did not change
  (`when={() => count > 10}` does not touch the DOM on every `count` write).
- A thunk is re-evaluated on every effect run — it may read reactive values itself.

### `resolveSource(src): T`

Reads a `ReactiveSource` value (plain value, thunk, `Signal`, `$()`); tracked
automatically inside `effect()`. Handy when writing your own components.

## 7. Resources and performance

| Operation | 1 000 | 10 000 | Environment |
| --- | --- | --- | --- |
| Build `Grid` (grouping + `rowKey`) | 64 ms | 1 480 ms | jsdom |
| Insert a ready grid | 5 ms | 44 ms | jsdom |
| Sort by click (2 clicks) | 96–102 ms | 7.6–9.3 s | jsdom |
| Keyed list update, same order | — | **1.8 ms** | jsdom |
| `Tree` search (filter + render) | 0.9 ms | 4.5 ms | jsdom |

jsdom moves nodes roughly 30× slower than a browser: absolute DOM numbers are inflated,
ratios are meaningful. Reproduce with `npm run build && npm run bench`
(or `BENCH_SIZES=1000`).

**Known performance limits:**

- `Tree` re-renders the whole tree on every snapshot (it is not keyed) — hence the
  default search debounce; 10k expanded nodes means 10k DOM nodes;
- there is no virtualization in `Grid` or `Tree`;
- `Reactive` tracks property reads through a `Proxy` — hot loops are better served by
  `Signal` or by `.target`.

## 8. Limits and missing features

| Missing | Consequence / workaround |
| --- | --- |
| SSR / hydration | `h()` and `<For>` use the global `document`; server rendering is impossible |
| Portals | mount into the needed node with `mount()` |
| Object `ref` | `ref={el => …}`, keep the reference yourself |
| `class` from objects/arrays | build the string yourself |
| Lazy `computed` | recomputation is eager; cache manually for expensive work |
| Multi-column sorting | `Grid` sorts by a single column |
| Virtualization | no render window |
| Error boundaries | effect errors go to `console.error`/`onError`; rendering is not intercepted |
| Auto-batching | synchronous writes run effects one by one; group them with `batch()` |

## 9. Components: `<Grid>`

```ts
function Grid<Row>(props: GridProps<Row>): HTMLElement;
```

A grid: filter → sort → group, with state local to the instance.

```ts
interface GridProps<Row> {
  rows: ReactiveSource<readonly Row[]>;
  columns: readonly Column<Row>[];
  filter?: (row: Row, loweredQuery: string) => boolean;
  groupBy?: (row: Row) => string | null;
  initialSort?: { key: string; dir: 'asc' | 'desc' };
  rowKey?: (row: Row) => unknown;
  searchPlaceholder?: string;
  searchDebounce?: number | false;      // 120 ms by default
  searchDebounceMinItems?: number;      // 200 rows by default
  empty?: string;
  labels?: Partial<GridLabels>;
  class?: string;                       // root, 'grid' by default
}

interface Column<Row> {
  key: string;                          // column id, remembers the active sort
  header: string;
  cell: (row: Row) => JsxChild;
  sort: (row: Row) => string | number;  // sort value and default search text
  sortable?: boolean;                   // default true
  class?: string;                       // td class
  headerClass?: string;                 // th class
}

interface GridLabels {
  search?: string;           // search aria-label, 'Search'
  searchPlaceholder?: string;// 'Search…'
  sortDirection?: string;    // control aria-label, 'Sort direction'
  descending?: string;       // '↓ desc'
  ascending?: string;        // '↑ asc'
  rows?: string;             // counter prefix, 'rows:'; '' keeps the number only
}
```

**Behaviour:**

- Default search is a case-insensitive substring over `String(sort(row))` of every
  column; a custom matcher is `filter(row, loweredQuery)` (`loweredQuery` is already
  lower-cased).
- Sorting: clicking a `th` sorts descending; clicking the same column again flips the
  direction; `sortable: false` disables it. One column at a time.
- Grouping: group order follows first occurrence in the sorted list; `groupBy` → `null`
  produces an ungrouped bucket rendered before the groups.
- `rowKey` enables the keyed mode: sorting moves nodes instead of recreating them.
  **Cells of existing rows are not updated** — see §11 "key = identity".
- The counter shows the number of rows after filtering (collapsed groups are still counted).
- Search debounce kicks in only from `searchDebounceMinItems` rows; `searchDebounce: false`
  disables it entirely.

**Accessibility:** `th[scope=col]`, `aria-sort` on the active column, the group row is
`tabindex="0"` with `aria-expanded` and toggles on Enter/Space, `aria-label` on the
search box and on the direction control.

## 10. Components: `<Tree>`

```ts
function Tree(props: TreeProps): HTMLElement;

interface TreeData {
  label: string;
  meta?: string;                          // secondary text; also searched
  children?: readonly TreeData[] | null;  // null/absent — a leaf
  labelClass?: string;
}

interface TreeProps {
  root: ReactiveSource<TreeData | null>;
  searchPlaceholder?: string;
  searchDebounce?: number | false;        // 120 ms
  searchDebounceMinItems?: number;        // 200 nodes
  showExpandAll?: boolean;                // bulk expand/collapse buttons, default false
  nodeKey?: (node: TreeData, path: string[]) => unknown;  // expansion key, path by default
  renderLabel?: (node: TreeData) => JsxChild;
  empty?: string;
  labels?: Partial<TreeLabels>;
  class?: string;                         // extra `.tree` class
}

interface TreeLabels {
  search?: string;           // 'Search'
  searchPlaceholder?: string;// 'Search…'
  matched?: string;          // counter prefix, 'matched:'; '' hides it
  expandAll?: string;        // 'Expand all'
  collapseAll?: string;      // 'Collapse all'
}
```

**Behaviour:**

- Search: a substring over `label` **and** `meta`; nodes with a matching descendant are
  kept; while the query is non-empty everything is expanded and matches get the `match`
  class.
- Expansion is stored by `nodeKey(node, path)` (the `label/label/…` path by default).
- `children: []` counts as a folder (renders a toggle with no children); `null` is a leaf.
- The snapshot is rebuilt on every data/query/expansion change and the tree re-renders
  as a whole (deliberate, see [COMPROMISES.md](./COMPROMISES.md)).

**Keyboard:** a single `Tab` stop (the root row), `ArrowDown`/`ArrowUp` move focus over
visible rows, `Enter`/`Space` toggles, `ArrowRight`/`ArrowLeft` expands/collapses. Focus
is restored to the same node after a re-render.

**Accessibility:** `role="tree"` + `aria-label` (the root label), `role="treeitem"` +
`aria-expanded`, `role="group"` on children.

## 11. Key = identity (the most important trap)

In the keyed `<For>` mode and in `Grid` with `rowKey`, a node whose key stayed in the
list is **not re-rendered**. Therefore:

```tsx
// ❌ the value freezes at first render
{ key: 'title', header: 'Title', sort: r => r.title, cell: r => r.title }

// ✅ point binding: the field updates, the node (and focus) survive
{ key: 'title', header: 'Title', sort: r => r.title, cell: r => <b>{$(r, x => x.title)}</b> }

// ✅ or a fingerprint key: the node is recreated on a real change
rowKey={r => `${r.id}:${r.updated}`}
```

`$()` inside `cell` works only when the row is a reactive proxy (`Reactive`); on a plain
array the binding resolves once.

## 1. Counter and text field

```tsx
import { mount, signal, $ } from 'bso5';

const count = signal(0);

mount(document.body, () => (
  <main>
    <button onClick={() => count.update(n => n - 1)}>−</button>
    <output>{$(count)}</output>
    <button onClick={() => count.update(n => n + 1)}>+</button>
  </main>
));
```

A text field — state lives in a signal, the value comes back into the DOM via `value`:

```tsx
const name = signal('');

const field = (
  <input
    value={$(name)}
    onInput={e => { name.value = (e.target as HTMLInputElement).value; }}
  />
);
```

Why: `$()` updates the `value` **property**, not the attribute, so the caret does not
jump while the user is typing. `count.update(fn)` reads the current value untracked,
which is safe inside a handler.

## 2. Lists: with and without a key

**Without `key`** — simple and predictable, the whole list re-renders:

```tsx
const history = signal<string[]>([]);

<ul>
  <For each={$(history)}>{item => <li>{item}</li>}</For>
</ul>
```

**With `key`** — nodes are reused and moved (focus, caret and CSS transitions survive):

```tsx
<For each={() => model.value.rows} key={row => row.id}>
  {row => <li>#{row.id} <input value={$(row, x => x.name)} /></li>}
</For>
```

Choice: if items contain inputs, media or animations — use `key`; a throwaway list of
plain strings does not need it.

## 3. Conditionals and tabs

```tsx
const tab = signal<'list' | 'stats'>('list');

<nav>
  <button onClick={() => { tab.value = 'list'; }}>List</button>
  <button onClick={() => { tab.value = 'stats'; }}>Stats</button>
</nav>

<Show when={() => tab.value === 'list'} fallback={() => <Stats />}>
  {() => <List />}
</Show>
```

Both branches are **thunks**: on a switch the old one is torn down completely (its
effects and bindings are released). Passing a ready node (`fallback={<Stats />}`) caches
it and keeps it alive while hidden — sometimes useful, but its subscriptions stay active.

## 4. Lists with the keyed mode

The key is identity. While a key stays in the list its node is **not re-rendered**, so
changed data does not appear by itself. Three working options:

```tsx
// a) the field updates in place; the row must be a reactive proxy
{cell: row => <b>{$(row, x => x.title)}</b>}

// b) fingerprint key: the node is recreated on a real change
<For each={() => model.value.rows} key={row => `${row.id}:${row.updated}`}>…</For>

// c) drop the keyed mode and accept full re-renders
<For each={() => model.value.rows}>…</For>
```

Preference order: (a) is cheapest and keeps focus; (b) is simpler but loses node state;
(c) only for small lists.

Same for `Grid`: `rowKey` enables the keyed mode, a `cell` with `$()` makes cells live.

## 5. Loading data

The recipe: one signal per state, errors in a separate signal, `finally` clears the
loading flag. No magical states.

```ts
import { signal } from 'bso5';

interface Issue { id: number; title: string }

const issues = signal<Issue[]>([]);
const loading = signal(false);
const error = signal<string | null>(null);

async function load(): Promise<void> {
  loading.value = true;
  error.value = null;
  try {
    const res = await fetch('/api/issues');
    if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
    issues.value = await res.json() as Issue[];
  } catch (e) {
    error.value = e instanceof Error ? e.message : String(e);
  } finally {
    loading.value = false;
  }
}
```

```tsx
<Show when={() => loading.value} fallback={() => (
  <Show when={() => error.value !== null} fallback={() => <List rows={issues} />}>
    {() => <p class="error">{$(error)}</p>}
  </Show>
)}>
  {() => <p>Loading…</p>}
</Show>
```

Nested `<Show>` looks bulky but reads top to bottom and needs no extra abstractions:
"loading → error → data".

## 6. Derived values

```ts
import { computed, signal } from 'bso5';

const items = signal<number[]>([]);
const total = computed(() => items.value.reduce((s, n) => s + n, 0));
const isEmpty = computed(() => items.value.length === 0);
```

`computed` is a regular `Signal`: it can go into `$()`, `each`, `<Show when>` and reads
inside `effect()`. If the result did not change, subscribers do not re-run (`Object.is`
comparison) — so `isEmpty` does not touch the DOM on every append.

## 7. A view with a lifecycle

```tsx
import { effect, mount, onScopeDispose, signal, $ } from 'bso5';

const target = document.getElementById('app')!;

const app = mount(target, () => {
  const seconds = signal(0);
  const timer = setInterval(() => seconds.update(n => n + 1), 1000);

  // the effect belongs to the mount scope: it stops with the view
  effect(() => console.log('tick', seconds.value));

  // your own cleanup goes through the same scope
  onScopeDispose(() => clearInterval(timer));

  return <p>{$(seconds)}</p>;
});

app.dispose(); // timer cleared, effect stopped, node removed
```

Why a thunk: everything created **inside** `() => …` gets an owner. A node built before
`mount()` has already created its effects outside any scope, and nothing can stop them.

## 8. Grid

```tsx
import { Reactive, signal } from 'bso5';
import { Grid } from 'bso5-components';
import type { Column } from 'bso5-components';

interface Issue { id: number; title: string; project: string; severity: string }

const model = new Reactive<{ issues: Issue[] }>({ issues: [] });
const query = signal('');

const COLS: Column<Issue>[] = [
  { key: 'id', header: 'ID', sort: i => i.id, cell: i => i.id },
  // a live cell: the row is a Reactive proxy, so $() updates in place
  { key: 'title', header: 'Task', sort: i => i.title, cell: i => <b>{$(i, x => x.title)}</b> },
  { key: 'severity', header: 'Severity', sort: i => i.severity, cell: i => i.severity },
];

<Grid
  rows={() => model.value.issues}
  columns={COLS}
  groupBy={i => i.project}
  rowKey={i => i.id}
  searchPlaceholder="Search tasks"
  labels={{ rows: 'rows:', descending: 'desc', ascending: 'asc' }}
  empty="Nothing found"
/>
```

- `rows` is a thunk so that replacing the whole array is picked up.
- `rowKey` + `$()` in `cell` — data updates while focus and selection survive.
- `filter` is needed when the default search over `sort(row)` is not enough:
  `filter={(row, q) => row.title.toLowerCase().includes(q) || row.assignee.toLowerCase().includes(q)}`.
- `initialSort={{ key: 'id', dir: 'desc' }}` is reflected both in the list order and in the direction control.

## 9. Tree

A flat list → tree → component:

```tsx
import { computed, signal } from 'bso5';
import { Tree } from 'bso5-components';
import type { TreeData } from 'bso5-components';

interface FileNode { path: string; name: string; size?: number; children?: FileNode[] }

const files = signal<FileNode[]>([]);

const toTreeData = (nodes: FileNode[]): TreeData[] =>
  nodes
    .slice()
    .sort((a, b) => Number(!!b.children) - Number(!!a.children) || a.name.localeCompare(b.name))
    .map(n => ({
      label: n.name,
      meta: n.size === undefined ? undefined : `${n.size} B`,
      children: n.children?.length ? toTreeData(n.children) : null,
    }));

const root = computed<TreeData | null>(() =>
  files.value.length ? { label: 'root', children: toTreeData(files.value) } : null);

<Tree
  root={root}
  nodeKey={node => node.label}          // expansion key: by label, not by path
  showExpandAll
  labels={{ matched: 'matched:', expandAll: 'Expand all', collapseAll: 'Collapse all' }}
  searchPlaceholder="Filter by name or size"
/>
```

- Sorting and building happen before the component: it renders what it is given.
- `meta` is searched too: put there whatever should be findable.
- `nodeKey` is required when labels may repeat or reorder.

## 10. Errors in effects

```ts
import { effect, setEffectErrorHandler } from 'bso5';

// locally
effect(() => riskyRendering(), { onError: err => toast(String(err)) });

// globally (e.g. in dev mode — log with context)
setEffectErrorHandler(err => console.error('[bso5]', err));
```

An exception in an effect is not propagated to the code that wrote the signal: one
broken view must not bring down the model. In tests the handler is handy to fail on the
spot:

```ts
setEffectErrorHandler(err => { throw err; });  // in a test — fail right there
```

## 12. Traps

| Symptom | Cause | What to do |
| --- | --- | --- |
| `[object Object]` in text | `$()` interpolated into a template string | bind the child/attribute, not a string |
| Data in a row does not update | keyed mode: key = identity | `$()` in the cell or a fingerprint key (§4) |
| `watch()` throws "requires a plain property path" | the accessor contains an expression or a method call | only a property chain: `x => x.a.b`, `x => x.rows[0].c` |
| `TypeError: Method Map.prototype.set called on incompatible receiver` | a `Map`/`Set` inside `Reactive` is not proxied, yet its method is called through a proxy | cannot happen on 0.4.0; if you see it, the object was wrapped manually |
| A binding "froze" at its first value | `$()` over a plain object (not `Reactive`) | wrap the model in `Reactive` or use `Signal` |
| An effect stops firing after a row is removed | the node is gone, its effect was stopped by the scope | expected: create effects inside a live render |
| The `onDoubleClick` handler never fires | old core (before 0.4.0) emitted `doubleclick` | upgrade bso5 |
| `<select>` ignores `value` | the value was applied before `<option>`s existed | handled in 0.4.0; when building by hand, set `value` after children |
| Memory grows on large lists | effects created outside any scope | create effects inside `mount()`/`<For>`/`<Show>` |
| A hidden tab keeps reacting | the `<Show>` branch was passed as a ready node | pass a thunk: `{() => <Tab />}` |

# bso5

Reactive DOM without the bloat. A tiny (~4.2 kB min+gzip) TypeScript library that gives you
signals, deep reactive state and first-class **JSX support — with no framework, no virtual DOM
and no compiler beyond the standard JSX transform**.

```tsx
import { Reactive, $ } from 'bso5';

const state = new Reactive({ count: 0, user: { name: 'World' } });

document.body.appendChild(
  <main>
    <h1>Hello, {$(state.value, x => x.user.name)}!</h1>
    <p>Count: <strong>{$(state.value, x => x.count)}</strong></p>
    <button onClick={() => state.value.count++}>+1</button>
  </main>
);
```

Updates are **fine-grained**: writing `state.value.count = 5` patches exactly one text node.
No component ever re-renders.

## Install

```sh
npm install bso5
```

Requires TypeScript ≥ 5.0 (for `react-jsx` + custom `jsxImportSource`) or any
esbuild/Vite-based build with the automatic JSX transform.

## Setup (JSX)

In your `tsconfig.json`:

```jsonc
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "bso5"
  }
}
```

For Vite (or plain esbuild) add the same options to `esbuild`:

```ts
// vite.config.ts
export default {
  esbuild: {
    jsx: 'automatic',
    jsxImportSource: 'bso5',
  },
};
```

No JSX? Use the `h()` factory directly — everything else works identically.

## Core concepts

| Export | Purpose |
| --- | --- |
| `Signal<T>` / `signal(v)` | Atomic reactive value: `.value` get/set, `.peek()`, `.update()`, `.subscribe()` |
| `Reactive<T>` | Deep reactive proxy over a plain object, with path subscriptions |
| `effect(fn)` | Auto-tracked computation: re-runs when anything it read changes |
| `watch(src, path, cb)` | Manual subscription to a `Signal` or a `Reactive` property path |
| `$(src, path?)` | Create a **bound value** for JSX children and attributes |
| `<For each={…}>` | Reactive list rendering; optional `key` enables DOM-node reuse |
| `<Show when={…}>` | Reactive conditional rendering, with an optional `fallback` |
| `h(tag, attrs, ...kids)` | Universal element factory (strongly typed per HTML tag) |
| `releaseBindings(root)` | Stop the reactive DOM bindings of a detached subtree |
| `Fragment` | JSX fragment; `bso5/jsx-runtime` — automatic JSX entry points |

### Signal

```ts
import { signal, effect } from 'bso5';

const name = signal('ann');

effect(() => {
  console.log(name.value); // 'ann', then 'bob'
});

name.value = 'bob';   // notifies subscribers and effects
name.peek();          // 'bob' — read without tracking
name.update(v => v + '!');  // update from current value (untracked read)
```

### Reactive

```ts
import { Reactive, watch } from 'bso5';

const state = new Reactive({
  user: { name: 'ann', address: { city: 'Rome' } },
  tags: ['a', 'b'],
});

// Watch a nested path — an accessor or a 'user.address.city' string.
watch(state.value, x => x.user.address.city, () => { /* ... */ });
// Index notation works too: 'rows.1.done' via accessor or string.
watch(state.value, x => x.rows[1].done, () => { /* ... */ });

state.value.user.address.city = 'Milan';  // fires the watcher
state.value.user = { name: 'bob', ... };  // re-binds nested paths automatically
state.value.tags.push('c');               // arrays supported (length tracked)
```

`.value` returns the reactive proxy tree; `.target` exposes the raw object
(reads/writes there are untracked). `dispose()` stops all subscriptions and
effect tracking — bindings go quiet while reads/writes through the proxy keep
working as a plain pass-through.


### Bound values: `$()`

`$()` is the bridge between state and markup. Use it as a **JSX child** or an
**attribute value** and it keeps the DOM up to date:

```tsx
<p>Count: {$(state.value, x => x.count)}</p>
<input value={$(state.value, x => x.name)} disabled={$(state.value, x => x.busy)} />
<div style={{ color: $(state.value, x => x.color) }}>colored</div>
```

- `$()` accepts a `Signal` (`$(countSignal)`) or a `Reactive` proxy + path accessor.
- The path accessor must be a **plain, pure property chain** (`x => x.user.name`;
  `x => x.items[0].title` — index notation supported). It is *executed* once per
  subscription to trace the path, so it must have no side effects. Computed
  expressions (`x => x.count + 1`) and method calls are rejected. Wrap those in
  `effect()` instead.
- Bound values can't be interpolated into template strings — `label={`+${$(...)}`}` renders
  `[object Object]`. Bind the attribute/child itself, not a string around it.

### Lists and conditionals: `<For>` and `<Show>`

JSX expressions evaluate **once** at mount. For reactive lists and conditions use
`<For>` / `<Show>` — they render between invisible comment anchors (no wrapper
elements, no re-render of the parent):

```tsx
import { For, Show } from 'bso5';

<ul class="history">
  <For each={() => state.value.history}>
    {(value, i) => <li>step {i + 1}: {value}</li>}
  </For>
</ul>

<Show when={() => state.value.count > 10}>
  <p class="alert">Too much!</p>
</Show>
```

`each` / `when` accept a plain value, a `() => value` thunk (re-read and
auto-tracked), a `Signal` or a `$()`-bound value. By default `<For>` re-renders
the whole list on change — keep item functions cheap; use `$()` inside them for
fine-grained bindings.

Pass a `key` to switch to **keyed reconciliation**: existing DOM nodes are
reused and moved (`insertBefore`) instead of being recreated, preserving focus,
caret, text selection, media state and CSS transitions across reorders. The
semantics are the usual React/Solid ones:

- the key identifies the element — **while the key stays in the list, the item's
  nodes are not re-rendered**: bind item fields with `$()` inside the render
  function rather than relying on fresh item data;
- the rendered `index` is captured at first render and does not update on
  reorder — bind it via `$()` if you need a live index;
- keys must be unique: duplicates collapse into a single group of nodes.

```tsx
<For each={() => state.value.rows} key={(row: Row) => row.id}>
  {(row) => <li>#{row.id} <input value={$(row, x => x.name)} /></li>}
</For>
```

A `<Show>` with a function child re-evaluates it every
time the block is shown, and an optional `fallback` (same shapes) is rendered
while the condition is false:

```tsx
<Show when={() => state.value.items.length > 0} fallback={<p>No items yet.</p>}>
  <ul>{/* … */}</ul>
</Show>
```

### `effect()` for full control

When you need something the declarative components don't cover — canvas
drawing, third-party widgets, manual DOM — use `effect()`. It tracks every
`Signal` and every `Reactive` property read inside it:

```tsx
import { effect, h } from 'bso5';

const list = h('ul', { class: 'history' });
effect(() => {
  const items = state.value.history;
  list.replaceChildren(...items.map((v, i) => h('li', null, `#${i}: ${v}`)));
});
```

The effect re-runs with fresh dependency tracking on every run, supports nested
effects and can be stopped via the returned function. Effects are also
resilient by design:

- an exception thrown inside an effect is logged via `console.error` and
  **never propagates into the code that wrote the signal** — one bad effect
  cannot take the app down;
- an effect that writes a value it also reads (`effect(() => { s.value++ })`)
  runs once instead of recursing infinitely — counters inside effects should
  use `s.update(n => n + 1)` / `s.peek()`, which read untracked.

When a view built with `$()` bindings is detached from the document, call
`releaseBindings(root)` to stop its subscriptions — removed nodes stop
receiving updates and become garbage-collectable.

### `h()`: attribute reference

`h(tag, attrs, ...children)` and JSX share one implementation, so this table
holds for both. `attrs` may also be a function: `h('input', el => el.focus())`.

| Key | Value form | What happens |
| --- | --- | --- |
| `class` / `className` | string | `el.className = value` (both work; the last one wins) |
| `style` | string or object | string → `setAttribute('style', …)`; object → `el.style[prop] = value` per property |
| `style` property | number | **always** gains `px` (`{ width: 10 }` → `10px`); unitless props (`opacity`, `zIndex`) must be strings |
| `style` property | `$()` | the property becomes reactive |
| `onClick`, `onInput`, … | function | `addEventListener('click' / 'input' / …)`; **camelCase required**, `onDoubleClick` maps to `dblclick` |
| `value`, `checked`, `selected`, `disabled` | any | assigned as a **property**, not a string; `<select>.value` is applied after its `<option>`s exist |
| `dataset` | object | `el.dataset[key] = String(value)` |
| `data-*`, `aria-*`, other | any | `setAttribute` when the element has no such property, property assignment otherwise |
| any key | `null` / `undefined` / `false` | `removeAttribute(key)` — the attribute is not set |
| any key | `$()` | applied now and kept in sync with the source |
| `ref` | — | **not supported**; use `h(tag, el => …)` or `effect()` |

Children: string and number → text node; `null`/`undefined`/`true`/`false` →
nothing; array → recursive; `Node` → as is; `$()` → a live text node.

```ts
import { h } from 'bso5';

const input = h('input', {
  type: 'text',
  class: 'field',
  style: { width: 200, color: 'tomato' },   // 200 → 200px
  disabled: false,                          // attribute not set
  dataset: { role: 'query' },               // data-role="query"
  'aria-label': 'Search',
  onInput: e => console.log((e.target as HTMLInputElement).value),
});
```

### Lifecycle: `mount()`, scopes, `batch()`

`<For>` and `<Show>` own the effects of their subtree: a re-render, a branch
switch or a removed key stops their effects and releases their DOM bindings.
For a whole view, use `mount()`:

```tsx
import { mount } from 'bso5';

const app = mount(document.body, () => <App />); // pass a thunk
app.dispose(); // bindings released, effects stopped, node removed
```

Pass a **thunk** (`() => <App />`), not a ready node: a view built before the
call has already created its effects outside any scope, and nothing can stop
them later.

Custom components build on the same primitives:

```ts
import { createScope, runInScope, dispose, onScopeDispose } from 'bso5';

const scope = createScope();
runInScope(scope, () => { /* effects created here belong to scope */ });
onScopeDispose(() => { /* cleanup on dispose(scope) */ });
dispose(scope); // everything created inside is stopped
```

`batch(fn)` postpones effect and listener runs until the end of the block: two
writes produce one run. `untrack(fn)` reads values without creating a
dependency.

```ts
import { signal, effect, batch, untrack } from 'bso5';

const a = signal(1);
const b = signal(2);
effect(() => { console.log(a.value, untrack(() => b.value)); });
batch(() => { a.value = 10; b.value = 20; }); // one effect run
```

### Components

A component is any function from props to a DOM node. No hooks, no re-renders —
components run exactly once:

```tsx
function Button(props: { label: string; onClick: () => void; kind?: string }) {
  return (
    <button class={`btn ${props.kind ?? ''}`} onClick={props.onClick}>
      {props.label}
    </button>
  );
}
```

# bso5-components

Reusable **headless data components** built on [bso5](../bso5): a generic data
`Grid` and a collapsible `Tree`. Bring your own data (any reactive source) and
your own CSS — the components render semantic markup with stable class names.

**~2.5 kB min+gzip** · zero dependencies (besides the `bso5` peer)

[Русская версия](./README.md)

Requires `bso5` (v0.4+) as a **peer dependency**. Install both:

```bash
npm install bso5 bso5-components
```

## Why a peer dependency?

The components share bso5's module-scoped `REACTIVE_VALUE` symbol: two copies
of bso5 in one bundle would produce two different symbols, silently breaking
`$()`-bound values. Keep exactly one copy — hence the peer dependency.

Working on the package itself requires Node ≥ 22.12 (vitest 5).

## `<Grid>`

```tsx
import { signal } from 'bso5';
import { Grid } from 'bso5-components';
import type { Column } from 'bso5-components';

interface Issue { id: number; title: string; severity: string; project: string }

const COLS: Column<Issue>[] = [
  { key: 'id',    header: 'ID',    sort: it => it.id,    cell: it => it.id },
  { key: 'title', header: 'Title', sort: it => it.title, cell: it => it.title },
  {
    key: 'severity',
    header: 'Sev',
    sort: it => it.severity,
    cell: it => <span class="sev">{it.severity}</span>,
    class: 'sev-cell',
  },
];

const issues = signal<Issue[]>(ISSUES);

<Grid
  rows={issues}                            // array | () => array | Signal | $()
  columns={COLS}
  groupBy={it => it.project}               // optional; null = ungrouped
  initialSort={{ key: 'id', dir: 'desc' }} // optional
  rowKey={it => it.id}                     // optional, enables keyed mode
  searchPlaceholder="Search…"
  empty="Nothing found."
/>
```

**Props `GridProps<Row>`:**

| Prop | Type | Description |
| --- | --- | --- |
| `rows` | `ReactiveSource<readonly Row[]>` | Array, `() => array` thunk (re-read, tracked), `Signal` or `$()` |
| `columns` | `readonly Column<Row>[]` | See below |
| `filter?` | `(row: Row, loweredQuery: string) => boolean` | Custom search matcher; the query is already lower-cased. Default: substring match over `sort(row)` of every column |
| `groupBy?` | `(row: Row) => string \| null` | Group label; `null` keeps the row ungrouped (rendered before the groups) |
| `initialSort?` | `{ key: string; dir: 'asc' \| 'desc' }` | Initial sort; reflected in the direction control |
| `rowKey?` | `(row: Row) => unknown` | Stable row key, enables keyed `<For>`. Called with the row **only** — the index is not part of the key, otherwise sorting would recreate every node |
| `searchPlaceholder?` | `string` | Search placeholder (also `aria-label`) |
| `empty?` | `string` | Empty-state text |
| `class?` | `string` | Extra class for the root (default `grid`) |

**Column `Column<Row>`:**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `key` | `string` | yes | Stable id; remembers which column is sorted |
| `header` | `string` | yes | `th` label |
| `cell` | `(row: Row) => JsxChild` | yes | Cell renderer; may return `$()` values |
| `sort` | `(row: Row) => string \| number` | yes | Sort value (and default search text) |
| `sortable?` | `boolean` | no | Header click sorts (default `true`) |
| `class?` | `string` | no | Extra `td` class |
| `headerClass?` | `string` | no | Extra `th` class |

**Keyboard and ARIA:** headers get `scope="col"` and `aria-sort`
(`ascending`/`descending` on the active column only); a group row is
`tabindex="0"` with `aria-expanded` and toggles on Enter/Space; the search box
has an `aria-label`.

## `<Tree>`

```tsx
import { signal } from 'bso5';
import { Tree } from 'bso5-components';
import type { TreeData } from 'bso5-components';

const tree = signal<TreeData>({
  label: 'bso5',
  meta: '7 items',
  children: [
    { label: 'src', meta: '6 items', children: [
      { label: 'index.ts', meta: '412 B', children: null },
    ]},
  ],
});

<Tree root={tree} searchPlaceholder="Filter…" />
```

**Props `TreeProps`:**

| Prop | Type | Description |
| --- | --- | --- |
| `root` | `ReactiveSource<TreeData \| null>` | Object, `() => object`, `Signal` or `$()` |
| `searchPlaceholder?` | `string` | Search placeholder (also `aria-label`) |
| `empty?` | `string` | Text when the tree is empty or filtered to nothing |
| `nodeKey?` | `(node: TreeData, path: string[]) => unknown` | Expansion key. Default: the `label/label/…` path |

**`TreeData`:** `label: string`, `meta?: string`, `children?: readonly TreeData[] | null`,

**Keyboard and ARIA:** the root is `role="tree"`, a node is `role="treeitem"` with

## Keyed mode: key = identity

With `rowKey`, `<For>` reuses DOM nodes: while a key stays in the list, its node is
**not re-rendered**, so data changes inside an existing row do not show up by
themselves. Two working recipes:

```tsx
// 1) bind the field with $() — a point update, the node survives
{ key: 'title', header: 'Title', sort: r => r.title, cell: r => <b>{$(r, x => x.title)}</b> }

// 2) fingerprint key — the node is recreated only when the data really changed
rowKey={r => `${r.id}:${r.updated}`}
```

The first keeps focus in an `<input>`; the second is simpler but loses node state
on every change. Without `rowKey` the grid re-renders rows wholesale — correct,
but more expensive.
