bso5 — оценка библиотеки и план доработок

Репозиторий github.com/evgwpw/BSO5, ветка main, HEAD 2937cab · MIT · оценка по фактической сборке, тестам и пробным прогонам · 2026-11-01

ВЕРДИКТ

Ядро — сильное, но библиотека пока не «готова к употреблению без чтения исходников».

Идея и реализация тонких привязок честные: 3.48 kB min+gzip, ноль зависимостей, keyed-<For> с перемещением узлов, 135 зелёных тестов, редкая по честности документация компромиссов. Но установка из репозитория падает, README компонентов описывает несуществующий API, а вне keyed-списков реактивность не освобождается (утечка подписок и эффектов). Для сценария «только h()» ядро пригодно уже сейчас — после починки установки. Все числа в этом вердикте — состояние на момент оценки (HEAD 2937cab); текущий статус правок — в разделе 0.

2. Что сделано хорошо

Честный размер и ноль зависимостей

3.48 kB min+gzip измерены и подтверждены; sideEffects:false, карта exports с ./jsx-runtime, ESM с корректными расширениями — пакет нормально резолвится и тришейкается.

keyed-<For> сделан правильно

Группы узлов на ключ, insertBefore перемещает, а не пересоздаёт; дубликаты схлопываются через next.get(k) ?? prev.get(k); ушедшие ключи проходят через releaseBindings. Это самая трудная часть, и она верна.

Документация компромиссов

docs/COMPROMISES.md — матрица из 23 форм аксессоров, замеры «было/стало», явно принятые издержки (побочные эффекты аксессора, мусорные пути). Такой документ дороже README.

Дисциплина peer-зависимости

Компоненты требуют ровно одну копию ядра и объясняют почему (REACTIVE_VALUE — свой у каждой копии). Тесты импортируют пакеты как потребитель, через alias.

Тесты поведенческие

jsdom, 135 штук, включая краевые случаи h(), отписки, перепривязку вложенных путей при замене предка. Не «покрытие ради покрытия».

Двуязычный JSDoc

Каждый экспорт описан по-английски и по-русски, включая @module. Для внутреннего инструмента это окупается.

3. Дефекты — подтверждены экспериментом

3.1 Ядро: реактивность не освобождается

<For> без key при каждом изменении делает clearBetween и вставляет узлы заново, но не вызывает releaseBindings и не останавливает эффекты, созданные внутри элементов. Подписки накапливаются, старые узлы продолжают обновляться.

PROBE B listeners before= 3  after= 18   (спанов в DOM: 3 — старые узлы живут как подписчики)
PROBE G effect runs after 5 re-renders = 6 | лишних прогонов на одну запись триггера = 6

Следствие: в Tree и Grid каждая перерисовка (а это каждый символ в поиске) добавляет работу, которая уже никому не видна. В Show с ребёнком-функцией та же дыра: toNodes() создаёт новые узлы, clearBetween убирает старые без releaseBindings.

3.2 Ядро: Reactive ломает Map и Set

PROBE A  st.value.m.set('a', 1) → TypeError: Method Map.prototype.set called on incompatible receiver #<Map>
         st.value.s.add(1)     → TypeError: Method Set.prototype.add called on incompatible receiver #<Set>

shouldProxy() исключает только Node, Date, RegExp. Любая модель с Map/Set (словарь сущностей, множество выбранных id — типичный шаг в интерфейсе) падает не при объявлении, а на первом вызове метода. То есть ловушка отложенная и тихая.

3.3 Компоненты: keyed-режим Grid не обновляет групповую строку

PROBE C  arrow before= ▾   arrow after click= ▾   (строк в tbody: 3 — группа схлопнулась, стрелка нет)
PROBE D  initialSort {dir:'asc'} → select.value = "desc"     (список отсортирован по asc — UI врёт)

Причина C: keyed-<For> переиспользует узлы по ключу, а стрелка читается через collapsedGroups.peek() — нереактивно, вне $(). Причина D: <select> не получает value из sortDir.

3.4 Компоненты: rowKey ломает сам смысл keyed-режима

rowKey(row, gridRow.index) получает индекс после фильтра и сортировки. При смене колонки сортировки ключи всех строк меняются → узлы пересоздаются, ровно в том сценарии, ради которого проп и обещан («сохраняет фокус при пересортировке»).

3.5 Tree: проп nodeKey мёртвый

PROBE E  nodeKey calls= 0   — ни одного вызова за создание + поиск

Состояние раскрытия всегда строится из String(path + label). В README prop описан как «ключ узла для состояния раскрытия» — то есть документация описывает несуществующее поведение.

Это прямое объяснение пункта «пропсы пришлось выяснять по исходникам»: документация есть, но доверять ей нельзя — а значит, она хуже отсутствующей.

3.7 Доступность и клавиатура — нулевые

Нет role="tree"/"treeitem", aria-expanded, aria-sort, aria-label у поиска; группа в Grid — кликабельный <tr>, на который нельзя попасть Tab'ом; узлы дерева не раскрываются с клавиатуры. Для внутренних инструментов терпимо, для «каталога примеров» — нет.

3.8 API-пробелы (из чужого опыта интеграции + чтение кода)

  • Нет таблицы атрибутов h() в README (пункт 1–2 из bso5-improvements.md так и открыт): class/className, style объектом/строкой, boolean-свойства, data-*, правила для null/false/массивов — всё есть в коде, но нигде не описано.
  • ref не поддерживается; onDoubleClick превращается в doubleclick (правильное имя события — dblclick) — тихий баг.
  • Нет mount(el, node), нет dispose() для вью, нет способа снять с дерева все эффекты поддерева (только $()-привязки).
  • Нет computed()/derived() — отсюда костыли вида const sortArrow = signal('↓'); effect(() => sortArrow.value = …) прямо в Grid.
  • Нет batch()/untrack(): каждая запись синхронно гоняет эффекты, N записей = N перерисовок.
  • Нет примера без сборщика (importmap + file://) — сценарий WASM.2b, единственный, который реально использовался.

4. План доработок

Порядок — по зависимостям, не по трудоёмкости: сначала то, без чего остальное нельзя проверить, затем корректность, затем документация, затем удобство.

Волна 0 — репозиторий должен ставиться и проверяться

Блокер: сейчас «Быстрый старт» из README не проходит первый шаг.

0.1Пересобрать package-lock.json
Удалить lock, поставить с npm ≥10, закоммитить. Готово, когда npm ci в чистом клоне проходит, а в lock нет записей без version (проверка: node -e по packages).
0.2Закрепить реестр: .npmrc с registry=https://registry.npmjs.org/
Чтобы lock снова не «отравился» внутренним реестром; в CI установка не зависит от машины.
0.3Объявить @types/node и engines
devDependencies + "engines": { "node": "^22.12 || ^24 || >=26" } + packageManager. Готово, когда npm run typecheck проходит на чистой установке без ручных доустановок. Причина границы: vitest 5 требует Node ≥22.12.
0.4CI: npm ci && typecheck && test && build
Матрица Node 22 / 24. Именно это ловит 0.1–0.3 в будущем: сейчас все три поломки видны только руками.
0.5Привести числа в README к фактам
1.5 → 1.95 kB у компонентов; требования к Node; убрать непроверяемые строки таблицы сравнения («сортировка 1000 узлов — 1 мс») или заменить ссылкой на npm run bench.

Волна 1 — владение реактивностью (главный архитектурный долг)

Без этого Tree/Grid нельзя ставить в долгоживущий интерфейс: каждая перерисовка оставляет за собой подписки.

1.1Ввести scope владения: createScope() / dispose(scope)
Каждый effect(), созданный внутри области (рендер элемента <For>, ветка <Show>), регистрируется в ней; clearBetween вызывает dispose области, а не только releaseBindings. Готово, когда пробник B даёт before = after после 100 перерисовок, а G — ноль лишних прогонов.
1.2Show с ребёнком-функцией: освобождать предыдущую ветку
Тест на 50 переключений: число подписок на сигнал не растёт.
1.3Публичный mount(el, node) → { dispose() }
Убирает boilerplate body.append(h(...)) и даёт штатный способ снять вью целиком (сейчас это невозможно без ручного обхода).
1.4shouldProxy(): не оборачивать Map/Set/WeakMap/WeakSet/Promise, Blob, File, AbortController
Пробник A даёт none / none. Тест: модель со словарём Map читается и пишется.
1.5batch(fn) и untrack(fn)
batch(() => { a.value = 1; b.value = 2; }) даёт один прогон эффекта вместо двух; untrack снимает ловушку «чтение внутри эффекта ради значения».

Волна 2 — документация, которая снимает вопросы

Ровно то, из-за чего в WASM.2b писали нативный DOM рядом с библиотекой.

2.1Справочник h() — таблица на одну страницу
Строки: class/className, style объектом и строкой (и реактивные значения внутри), on* в camelCase (с исправлением onDoubleClick → dblclick), boolean-свойства (disabled/checked/value), data-* и dataset, null/false/undefined и массивы среди детей, «атрибут vs свойство» (правило key in el), явная строка «ref не поддерживается».
2.2Переписать README компонентов по коду и защитить его тестом
header, обязательный sort, реальные сигнатуры rowKey/nodeKey, empty: string, класс match. Готово, когда примеры из README вынесены в docs/examples/*.tsx, которые компилируются в typecheck.
2.3Пример «без сборщика»: importmap + file://
examples/importmap/index.html с <script type="importmap"> на packages/*/dist, монтирование через h(), работающий из file:// и через любой статический сервер. Это ровно сценарий WASM.2b.
2.4docs/TREE_GRID.md: разметка, карта классов, минимальный CSS
Полный список классов + готовый CSS (взять из examples/dataview/style.css) + рецепт «как адаптировать свои данные». Без этого «headless» = «разберитесь сами», и компоненты не берут.

Волна 3 — корректность и эргономика компонентов

Чинятся ровно те места, где сейчас компонент врёт о своём состоянии.

3.1Grid: стрелка группы и initialSort
Стрелка через $(collapsedGroups)-производную (или перерисовка групповой строки при смене её состояния); <select value={$(sortDir)}> и обработчик change вместо односторонней записи. Тесты: пробники C и D дают ▸ и asc.
3.2Grid: ключ строки не должен зависеть от позиции
rowKey(row) без индекса в ключе; исходный индекс передавать отдельным пропом/полем, если нужен. Тест: после клика по заголовку узлы строк переиспользуются (проверка по идентичности DOM-узла).
3.3Задокументировать «ключ = идентичность» рецептом для данных
В README компонентов: при том же ключе ячейки не перерисовываются — либо $() внутри cell, либо ключ с отпечатком (id + ':' + updated). Сейчас это ловушка без выхода.
3.4Tree: оживить nodeKey
Ключ раскрытия = nodeKey(node, path) с дефолтом «путь». Пробник E даёт calls > 0.
3.5Доступность и клавиатура
role="tree"/"treeitem", aria-expanded, aria-sort на активном th, aria-label у поиска, группа — button внутри th/td или tabindex="0" + Enter/Space; в дереве — стрелки вверх/вниз/вправо/влево. Тесты на фокус.
3.6Производительность и замеры вместо маркетинга
npm run bench: 1k/10k строк и узлов, фильтр → сортировка → рендер; в README — числа из бенча. Плюс дебаунс поиска (или batch из 1.5), иначе каждый символ перестраивает дерево целиком.

Волна 4 — что сделает библиотеку приятной

Не блокирует использование, но убирает повторяющиеся костыли.

4.1computed(fn) / производные значения
Лениво пересчитываемое значение с кэшем и автотрекингом. Убирает пары «signal + effect + ручная запись» (сейчас такие есть даже внутри Grid).
4.2ref, on*Capture, поддержка class объектом/массивом
ref={el => …} вызывается после создания элемента; onClickCapture ставится с { capture: true }; class={{ active: true }} склеивается.
4.3Консистентность экспортов и @internal
applyAttr либо экспортируется из index, либо помечен @internal; hEl, flattenChildren, appendChildren — с пометкой уровня API.
4.4SSR-совместимость (по потребности)
h()/For не падают без document; при желании — renderToString. Нужно только если цель — серверный рендер; сейчас цель явно клиентская.

5. Если брать только под WASM.2b

Минимальный набор, после которого библиотеку можно вендорить без «нативного DOM рядом»: 0.1–0.3 (установка и lock), 2.1 (таблица h()), 2.3 (пример importmap под file://), 1.3 (mount/dispose). Tree/Grid в этом сценарии не нужны — и это подтверждает, что проблема была не в компонентах, а в отсутствии документации и способа монтирования.
