# Документация bso5

Два входа в одну и ту же документацию: по задачам (человеку) и точечными кусками
(агенту). Источник истины — Markdown в репозитории; типы и пропсы генерируются из
кода, примеры компилируются и исполняются, поэтому расхождение ловится машинно.

Языки: основная документация — русская, справочник и рецепты есть и по-английски
([API.en.md](./API.en.md), [GUIDE.en.md](./GUIDE.en.md)); README пакетов — в обоих
языках.

## Я человек

Читать в таком порядке:

1. [README пакета ядра](../packages/bso5/README.md) — 10 минут, идея и основные
   концепции (`Signal`, `Reactive`, `$()`, `<For>`, `<Show>`).
2. [GUIDE.md](./GUIDE.md) — рецепты под задачи: счётчик, список, загрузка данных,
   грид, дерево, вью с жизненным циклом.
3. [API.md](./API.md) — справочник, когда нужны точные сигнатуры и крайние случаи.
4. [PROPS.md](./PROPS.md) — таблицы пропсов, сгенерированные из TypeScript-типов.
5. [TREE_GRID.md](./TREE_GRID.md) — разметка, классы и минимальный CSS компонентов.
6. [COMPROMISES.md](./COMPROMISES.md) — почему сделано именно так и чем за это платим.

## Как эта документация поддерживается

| Правило | Чем обеспечено |
| --- | --- |
| Примеры из README и рецептов не расходятся с кодом | `docs/snippets/*` входят в `npm run typecheck` |
| «Что получится» проверяемо, а не описано словами | [`packages/bso5-components/tests/recipes.test.tsx`](../packages/bso5-components/tests/recipes.test.tsx) фиксирует итоговый DOM рецептов |
| Пропсы и их типы актуальны | `docs/PROPS.md` генерируется из интерфейсов (`npm run docs:props`) |
| Темы для точечного чтения актуальны | `docs/topics/*` нарезаются из `API.md` (`npm run docs:topics`) |
| Сводные файлы для LLM актуальны | `npm run docs:check` сверяет `llms-full*.txt`, `PROPS.md`, темы и все ссылки с якорями |
| Обещания про производительность не выдуманы | числа из `npm run bench`, команда в README |
| Ломающие изменения описаны | [`CHANGELOG.md`](../CHANGELOG.md) |

```bash
npm run docs:llm     # пересобрать llms-full.txt и llms-full.en.txt
npm run docs:props   # пересобрать PROPS.md из типов
npm run docs:topics  # пересобрать docs/topics/*
npm run docs:check   # проверить всё перечисленное + ссылки и якоря (это делает CI)
npm run typecheck    # проверить компилируемые сниппеты
npm run docs:html    # одностраничный HTML-справочник (.qwen/tmp, в git не попадает)
```

Правя API: меняйте `API.md`/`GUIDE.md` в обеих языковых версиях, затем прогоняйте
`docs:props && docs:topics && docs:llm && docs:check`. `docs:html` собирается из тех
же `.md`, поэтому «второй версии правды» не появляется.

## Состав `docs/`

| Файл | Про что |
| --- | --- |
| `API.md` / `API.en.md` | полный справочник: сигнатуры, семантика, ограничения |
| `GUIDE.md` / `GUIDE.en.md` | рецепты по задачам и таблица грабель |
| `PROPS.md` | пропсы и опции, сгенерированные из типов (генерируется) |
| `topics/`, `topics/en/` | короткие темы из разделов справочника (генерируются) |
| `TREE_GRID.md` | разметка `Grid`/`Tree`, карта классов, минимальный CSS (только рус.) |
| `COMPROMISES.md` | осознанные компромиссы реализаций (keyed-`<For>`, Proxy-пути, владение эффектами) |
| `snippets/` | компилируемые копии примеров из README и рецептов (входят в `typecheck`) |
| `REVIEW-2026-11-01.html` | снимок внешней оценки библиотеки и плана доработок (исторический документ) |
